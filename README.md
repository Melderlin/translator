# Англо-русский медицинский глоссарий: женская репродуктивная система

Сайт: **https://melderlin.github.io/translator/**

Глоссарий подготовлен по документу *Lecture Female Reproductive System – Anatomy, Histology, Physiology and Pathology.docx*. Содержание структурировано по восьми разделам. В записях есть английский термин, русский эквивалент, русская фонетическая подсказка, определение по лекции, теги и ссылки на связанные термины.

## Что есть в карточке термина

- \`id\`: уникальный стабильный идентификатор, например \`uterus:endometrium\`.
- \`glossary\`: ID раздела, к которому относится термин.
- \`term_en\`: английский термин.
- \`term_ru\`: русский перевод или эквивалент.
- \`pronunciation_ru\`: приблизительная подсказка о произношении английского выражения русскими буквами. Ударный слог помечен заглавными буквами.
- \`definition_ru\`: краткое русское определение, составленное по лекции.
- \`tags\`: массив тегов для тематической фильтрации.
- \`related\`: массив ID связанных терминов.

**Важно о произношении:** это практическая подсказка, а не Международный фонетический алфавит (IPA). Реальное звучание зависит от акцента и контекста; для учебной или клинической работы произношение сложных терминов желательно сверять с авторитетным словарём или преподавателем.

## Как удалены демонстрационные данные

Файл \`data/glossaries.json\` теперь содержит список разделов и перечень файлов с терминами, а не тестовые записи. Реальные записи хранятся отдельно в каталоге \`data/terms/\`. Чтобы исключить термин из сайта, удали его объект из соответствующего JSON-файла, затем убери ссылки на его ID из массивов \`related\` других терминов.

## Как добавить новый термин

1. Открой на GitHub один из файлов в \`data/terms/\`, соответствующий разделу. Например, термины матки находятся в \`uterus-a.json\` и \`uterus-b.json\`.
2. Нажми значок карандаша **Edit this file**.
3. Добавь новый объект внутрь массива. Между объектами должна быть запятая:

   \`\`\`json
   {
     "id": "uterus:new_term",
     "glossary": "uterus",
     "term_en": "new term",
     "term_ru": "русский эквивалент",
     "pronunciation_ru": "НЬЮ тЁРМ",
     "definition_ru": "Краткое определение на русском языке.",
     "tags": ["anatomy", "uterus"],
     "related": ["uterus:endometrium"]
   }
   \`\`\`

4. Проверь, что \`id\` уникален. Используй формат \`раздел:понятие_в_нижнем_регистре\`, без пробелов.
5. Значение поля \`glossary\` должно совпадать с ID нужного раздела.
6. Теги — обычные строки. Одинаковое написание означает один и тот же тег в разных разделах. Для сквозной фильтрации используй одинаковые короткие теги, например \`heart\`, \`inflammation\`, \`histology\`, \`pathology\`, \`diagnostics\`.
7. В \`related\` указывай существующие ID терминов. Для двусторонней навигации добавь новый ID также в \`related\` связанного термина.
8. Нажми **Commit changes**. GitHub Pages обновит опубликованный сайт автоматически.

### Правила JSON

- Используй двойные кавычки для имён полей и текстовых значений.
- Между соседними объектами нужна запятая.
- После последнего объекта массива запятую ставить нельзя.
- Не добавляй комментарии в JSON.
- Не используй повторно существующий ID.

## Как добавить целый новый раздел (глоссарий)

1. Создай файл, например \`data/terms/neurology.json\`. Внутри него должен быть JSON-массив терминов.
2. В каждом объекте укажи \`"glossary": "neurology"\`.
3. Открой \`data/glossaries.json\` и добавь объект в массив \`glossaries\`:

   \`\`\`json
   {"id":"neurology","name_en":"Neurology","name_ru":"Неврология"}
   \`\`\`

4. Добавь путь к файлу в массив \`term_files\` в том же манифесте:

   \`\`\`json
   "terms/neurology.json"
   \`\`\`

   Не забудь запятую между соседними элементами массива.
5. Закоммить изменения. Новый раздел и его термины появятся после публикации.

## Как устроена загрузка и офлайн-фильтрация

При первой загрузке браузер скачивает HTML, CSS, JavaScript, манифест и перечисленные в нём файлы терминов. JavaScript загружает JSON через \`XMLHttpRequest\` (ES5-совместимо) и объединяет термины в памяти. После завершения загрузки смена раздела, тегов, поиск, открытие связанных карточек и переходы по хешу URL выполняются локально и не должны создавать новые сетевые запросы.

### Как убедиться, что фильтры не делают сетевых запросов

1. Открой сайт в Chrome на компьютере, открой DevTools → **Network** и включи сохранение журнала. Для iPad Safari можно использовать Safari Web Inspector на Mac.
2. Перезагрузи сайт один раз и дождись отображения терминов.
3. После полной загрузки выбери тег \`inflammation\`, затем другой раздел, найди термин и открой связанную карточку.
4. Убедись, что после завершения первоначальной загрузки Network не показывает новых запросов к JSON, CSS или JavaScript при этих действиях. URL hash меняется без перезагрузки документа.

При полном повторном открытии или перезагрузке страницы браузер может снова запросить ресурсы. Сайт не использует сторонние CDN, API, базы данных, тяжёлые фронтенд-фреймворки или Service Workers.
